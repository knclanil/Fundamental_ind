# Fundamental_ind 6.0.3 — resumable acquisition

Replace the repository contents (including hidden `.github` files) with this package. Remove old Python scripts/workflows from previous releases. Keep existing TURSO_DATABASE_URL and TURSO_AUTH_TOKEN secrets. Enable the Nifty 500 fundamentals workflow and dispatch it once. The pipeline initializes an empty database automatically; it refuses an unversioned nonempty database. No destructive SQL is executed. Do not use on the US database.

Core statements are collected first. Each company is checkpointed, and subsequent runs resume pending/failed/partial companies and refresh successful companies after seven days. A six-hour retry delay and five-failure run stop are conservative defaults. Extended acquisition is separate: `python fleet.py --group EXTENDED --limit 500 --minutes 300` with the same secrets; do not run concurrently with core. Core completion means annual P&L/BS/CF are present, not full historical coverage. Missing data is not zero. All data is unverified; scope is unknown. The ticker overrides are user-supplied and not live verified.

SQL: `SELECT * FROM vw_fund_acquisition_progress;` and `SELECT * FROM vw_fund_pnl_wide;`. BS and CF wide views are also available. Wide columns use INR crore and USD million, native EPS and shares; consult `vw_fund_cells` for units and conflicts. Unknown units remain null in wide views. Exact source decimal strings remain in history. Compressed payloads are gzip binary; verify SHA-256 after decompression. Snapshot status gates visibility of incomplete writes. Staging records are retained for audit, not automatically removed. The storage guard checks occupied pages before each company; it is not a hard provider quota guarantee.

The schema differs from the earlier proposed 25-table design: it uses fewer tables and combines unit/classification dimensions with metric metadata, storing repeated values once and linking snapshots. Market history is compressed JSON, not normalized OHLC rows. No official exchange backfill, independent verification, separate standalone/consolidated feeds, full ratio suite, or automatic backup is implemented. No live Turso or Yahoo testing was possible in this environment. Local tests cover schema initialization, legacy refusal, deduplication, revisions, compression and wide output. The prior historical database was reset by the user; it cannot be reconstructed exactly from this package.

## 6.0.3 — bounded, resumable module acquisition
Replace the repository files and push main; keep the database and secrets. The additive misc_module table and vw_fund_module_progress view initialize automatically under schema 6.0. Existing COMPLETE snapshots bootstrap available modules, without reacquiring them until due. Each company commits its results before the next; interrupted RUNNING entries remain eligible on a later run. Summary JSON is atomically replaced after each company. Runs are limited to 50 companies or 40 minutes (soft deadline between companies), with a 55-minute job timeout. CORE and EXTENDED retain separate hourly schedules and shared concurrency. Unchanged universe avoids repeated seed writes.

Prices and shares are required; optional empty responses are NOT_AVAILABLE (provider returned no usable data, not proof of no events). Exceptions and empty required modules are RETRY_PENDING. AVAILABLE refreshes after seven days, NOT_AVAILABLE after 30 days, RETRY_PENDING after six hours. Only due modules are fetched. PUBLISHED_UNVERIFIED means required modules available and no outstanding module retries; it does not imply all optional datasets exist or that values are independently verified. Previously published payloads remain intact. Module status is the latest attempt, not a deletion of older data. A failed publication is retried at company level. No confirmed NO_EVENTS classification is attempted because Yahoo empty results cannot establish absence. Module progress covers initialized companies only. The storage guard remains 380 MB occupied; provider quota and live runtime are unverified. GitHub scheduling may delay or replace pending runs; the next scheduled run resumes from persisted queue state. No live Yahoo/Turso tests were performed.

## Release 7.0 — Indian membership intelligence

Additive migration of 6.0.3: retain schema version 6.0 for financial compatibility. No reset. Deploy all files including hidden `.github` and tests; retain existing Turso secrets. The MEMBERSHIP dispatch is optional; scheduled runs at 02:52, 08:52, 14:52, 20:52 UTC check due sources (daily success refresh, six-hour failure retry). CORE/EXTENDED schedules and shared concurrency remain. GitHub concurrency can replace pending jobs; no guarantee of exact timing.

`india_index_sources.json` contains all 31 exact URLs from the supplied archived source register (20 November 2026), plus existing Nifty 500. Expected counts for named factor indices are inferred from names, not independently confirmed. Variable-size first snapshots are structurally checked only; subsequent count changes are rejected pending review, even legitimate changes. Equal Weight remains strategy; Energy retains the archived sector category. No live endpoint or Turso validation performed. No paid data.

`membership.sql` is additive. `dm_index` and `dm_factor` are integer dimensions; `br_index_factor` supports multiple factors; `dm_data_source` records URLs and health. `ft_index_snapshot` records observed UTC timestamp, normalized content SHA256, count and publication state. `ft_index_event` stores only additions/removals, and the history view derives half-open intervals. Initial additions are baseline observations, not official rebalances. Unchanged content updates source freshness only. STAGING/ABANDONED events are invisible. Identity matching uses ISIN and rejects conflicting symbols; outside-universe companies are inactive and receive no financial queue. `dm_industry` and `ft_classification_event` record benchmark industry labels, not a verified economic hierarchy. `misc_constituent_reconciliation` records identity conflicts. Existing company IDs and financial facts are retained. Storage guard uses occupied bytes (380 MB); no hard transaction-level quota guarantee.

Query `vw_company_membership_summary`, `vw_company_factor_current`, `vw_sector_constituents`, `vw_index_membership_history`, `vw_company_fundamental_membership`, `vw_index_source_health`. Join wide financial views on symbol or join facts on company_id; filter factors with EXISTS to avoid double counting. Point-in-time query: `SELECT * FROM vw_index_membership_history WHERE valid_from <= :asof AND (valid_to IS NULL OR valid_to > :asof)`. Dates are observed, not official effective dates. Evidence JSON arrays follow SQL view column order; source health includes failure details.

Limitations: no independent completeness verification, official weights, economic sector hierarchy, historical backfill, automatic source discovery/fallback, or live remote test. Count changes require operator review and a future explicit acceptance mechanism. Factor membership is not an independent factor score. Registry supports adding new indices and multifactor mappings by configuration; removing existing mappings requires explicit migration. Source failures preserve published membership. No guarantee of recovery of unobserved changes between refreshes. This is a locally tested initial release, not a production-verified full specification implementation.
